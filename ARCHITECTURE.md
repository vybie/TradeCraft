# Architecture and standards audit

TradeCraft is an independent alpha application, not an official Craft app. This audit compares the project with the [shared Craft contributor rules](https://github.com/storytold/craft-contrib), including the [core house rules](https://github.com/storytold/craft-contrib/blob/main/standards/house-rules-core.md) and [Rust house rules](https://github.com/storytold/craft-contrib/blob/main/standards/house-rules-rust.md). The workspace layering pattern is informed by the public [Craft Anything architecture](https://github.com/storytold/craft-anything/blob/main/AGENTS.md); project-specific requirements in that document are not automatically universal Craft requirements.

## Workspace

Dependencies point down this list:

1. `tradecraft-core`: market bars, intervals, and timestamps. It has no UI or provider dependencies.
2. `tradecraft-providers`: Yahoo, Tradier, and Kraken adapters, credential storage, and settings persistence. It uses the core market types, not chart-widget types.
3. `tradecraft-engine`: candle and workspace state, a command registry, a bounded JSON command runner, provider settings, and the background market-stream lifecycle. It does not depend on egui.
4. `tradecraft-ui-egui`: egui chart rendering and the desktop interface. It translates core bars into chart-widget bars.
5. `tradecraft`: the desktop entry point.

`cargo xtask layers` checks direct workspace dependency direction and prevents core, provider, and engine crates from directly depending on UI toolkits. `cargo xtask licenses` checks the Windows normal dependency graph with all workspace features against the Craft allowlist and currently reports failures described below. A different Cargo target can be supplied, for example `cargo xtask licenses aarch64-apple-darwin`; that target's dependency metadata must be available locally. Run `cargo test --workspace` for the community configuration and `cargo test --workspace --all-features` to include the personal credential feature.

## Community release disclosure

### Dependency-notice checks (November 13, 2026)

`scripts/license-audit.py` checks the locked normal application dependency graph against the change-detection baseline in `licenses/dependency-baseline.json` and assembles locally available license files, selected upstream supplements, and font and icon notices. It stops when package identities or declared expressions change, or when it cannot find license text; the macOS packaging script explicitly records missing texts as warnings instead. A baseline entry records a package and expression; it is not a legal approval, a license choice, or proof that all copyright notices have been found. Review source, notices, license alternatives and distribution obligations before updating it with `--snapshot`. Build/dev dependencies, assets not represented by Cargo, service terms, and source provenance still need human review. Raw `cargo build` bypasses these scripts.

The personal build script runs this check and writes notices alongside its pinned executable; `scripts/build-community.ps1` checks before building and packaging, and the macOS script places the notice bundle inside the app. `.github/workflows/license-audit.yml` checks both Windows feature configurations and both macOS targets on pushes and pull requests once the workflow is committed and run. Direct redistribution of an executable needs its accompanying notice directory. Python 3 is required; on Windows `TRADECRAFT_PYTHON` may select its executable.

The GitHub macOS runner reported a failure in the headless `market_data_settings_are_accessible` UI test. The macOS build workflow runs that test separately and reports its result without blocking packaging; the rest of the provider and UI tests remain blocking. The test passed separately on both architectures in the subsequent run; the original failure cause and real Mac settings interaction still need verification.

The November 13 local Windows normal graphs contain 271 package versions for each configuration, and both checks pass notice availability with the explicitly documented provisional supplements. The clock's system time-zone lookup adds `iana-time-zone` 0.1.65 on Windows; its published package includes MIT and Apache-2.0 license texts. Both macOS normal graphs contain 264 package versions, including that crate already. Strict checks report missing license texts for `dispatch` 0.2.0 and nine newer objc2-family package versions; their published crates omit license files and complete copyright notices remain unverified. The macOS package inventory records these gaps, and packaging warns rather than stopping for missing texts. The GitHub macOS workflow built and checked both Apple Silicon and Intel packages on November 14, 2026; interactive Mac validation remains outstanding. The advertised egui 0.37.0 source revision and enum-map-derive license-file provenance are also unresolved. See `licenses/upstream/README.md`. A passing automated check is not a compliance sign-off.

The terminal manifest now locally declares MIT OR Apache-2.0 based on the upstream repository's general license statement at the tracked revision; upstream's terminal manifest lacks a declaration. The adapted Pine fork's MIT text at its cited revision matches the vendored MIT notice. The pre-existing Craft allowlist findings remain separate from this audit.

This document is the public log of TradeCraft's Craft architecture and standards findings. Open findings do not by themselves prevent an informal community preview on the project owner's GitHub; the project does not claim full Craft compliance while they remain open. For each release, update this log with the current findings and check results, link the version of this document associated with the release in the release notes, and include it with any downloadable release package. Do not suppress or weaken checks to make the log look clean. Third-party license obligations and market-data distribution rights remain separate matters to review and disclose.

The current Windows dependency baseline also includes `regex` 1.13.1, `regex-automata` 0.4.18 and `regex-syntax` 0.8.11 (MIT OR Apache-2.0), and `aho-corasick` 1.1.5 (Unlicense OR MIT). Their packaged license files were checked; the Unlicense identifier remains subject to the existing strict Craft allowlist review. The macOS dependency baseline and build require separate verification.

## Findings and remaining work

- TradeCraft began as a single binary crate, with market data coupled to `egui-charts` and live candle logic in the UI. The workspace now has separate crates and a UI-independent engine. Existing Git history is preserved; the initial commit was made after the initial code already existed and cannot be changed without rewriting history.
- The upstream egui-charts terminal owns the live GUI's chart, indicator and layout state. The existing engine remains UI-independent and supports the isolated `--commands` and `--script <path>` interface; those commands do not control the terminal window. The terminal feed adapter is in the UI crate and calls the provider and engine layers. A comprehensive command registry covering every UI action and an MCP server are not implemented.
- The egui-charts source is vendored at `vendor/egui-charts`. Its upstream revision is recorded in `vendor/EGUI-CHARTS-UPSTREAM`; local modifications include host integration, data services and session controls. The scheduled GitHub workflow compares that revision with upstream `main` and opens or updates an issue when they differ. It also opens one tracking issue per newly observed stable upstream release. It does not merge changes automatically. Review the full vendored diff and validate personal Windows, community Windows and macOS builds when updating the dependency; retain its upstream license files, font and icon notices.
- The terminal's file storage saves named documents using encoded names and a temporary-file rename. Saved layout and drawing restoration, crash recovery, and multi-process conflicts need further verification. Alert definitions and statuses are saved locally; evaluation operates only while the app runs. Tradier charts and watchlists share one dynamically updated market stream; initial quotes use REST snapshots. Yahoo watchlist quotes use delayed REST data. Symbol search combines the selected provider with Kraken crypto pairs. The experimental Pine editor uses an adapted interpreter from DimmOFF's egui-charts fork; its subset and output require further compatibility, resource and live-data verification.
- The chart-tab strip saves open chart workspaces in terminal settings and restores them on startup or after changing providers. Switching tabs pauses inactive chart feeds while the watchlist uses the shared Tradier stream. Experimental Pine studies embed their applied source in the snapshot; the last complete snapshot is retained when an unregistered study cannot be serialized. Named layouts remain separate. File storage uses OS file locks and revision checks for settings and drawing conflicts. Workspace restart coverage uses an in-memory store; full process-crash recovery and cross-process behavior still need end-to-end verification.
- On a Tradier stream reconnect, chart recovery requests the missing historical range, restores completed bars, then reconciles the forming candle using complete one-minute bars and buffered later ticks. The chart reports recovery or errors; Tradier's intraday retention limits apply. Initial-load history overlap, provider corrections and late trade reconciliation remain open, and recovery under real market-hour interruptions needs further verification.
- Tradier weekly and monthly bars use provider history and reconcile the current calendar period from daily and one-minute bars. Individual-tick history uses bounded time-and-sales requests, including extended hours when enabled; availability varies by symbol and session. Recovery covers at most ten minutes. Since historical prints lack unique trade IDs, ticks sharing a millisecond at the history/live boundary cannot be reconciled exactly, and delayed provider history may leave gaps. Other trade-derived interval types remain unimplemented.
- Production crate roots forbid unsafe code and deny the Craft-listed panic-related Clippy lints. HTTP responses, WebSocket message/frame sizes, the market-event queue, scripts, and workspace collections are bounded. Stopping a session releases a producer waiting on a full queue. A broader input/resource audit remains incomplete.
- The existing Windows normal dependency graph contains license expressions with identifiers outside the Craft allowlist, including Zlib, 0BSD, BSL-1.0, GPL-2.0-only and Unlicense. `foldhash` (Zlib) is used through the egui/wgpu stack. The TLS adapters now use the operating system's trusted certificate store instead of the `webpki-roots` dependency, removing the latter's CDLA-Permissive-2.0 from the normal graph. `cargo xtask licenses` intentionally fails until the remaining reported entries are resolved. Other target platforms and build/dev dependencies need a separate audit. The embedded default-font notices are recorded in [ATTRIBUTION.md](ATTRIBUTION.md).
- Enabling the upstream terminal adds three further Windows license-check findings: `csv` and `csv-core` report `Unlicense/MIT`, and `egui-charts-terminal` declares no package license in its manifest. The upstream repository states MIT or Apache-2.0 licensing; package-level attribution and compliance require review. The user elected to track these issues here while continuing the integration. The checker remains unchanged and continues to report them.
- As of November 2026 the shared Rust rules say every identifier in an SPDX expression must be on the allowlist, even in an `OR` expression. That is stricter than simply choosing an offered MIT or Apache-2.0 alternative. The [VectorCraft lockfile](https://github.com/storytold/vectorcraft/blob/main/Cargo.lock) also lists `foldhash` and `memchr`, while its [desktop manifest](https://github.com/storytold/vectorcraft/blob/main/apps/vectorcraft/Cargo.toml) describes some dependencies with expressions containing Zlib. A lockfile can include inactive dependencies, so this is not evidence of an approved exception or of what VectorCraft ships. Clarification from the Craft maintainers, or tested compatible replacements that satisfy the rule as written, is needed before claiming compliance.
- The Yahoo endpoint is unofficial and Yahoo restricts automated access. Distribution rights and a suitable replacement data source remain unresolved.
- Kraken spot pairs use its public instrument catalog, ticker and candle streams. Charts refill recent history on reconnect, subject to Kraken's 720-candle spot-history limit. Kraken data redistribution terms for community releases have not been verified.
- Kraken asset search prefers a USD market per asset, retains explicit pair searches and the original market key, and retrieves names from public market metadata with a bounded lookup and ticker fallback. A small built-in fallback enables common full-name searches before metadata is cached; searching other full names before their ticker has been looked up is not yet supported. The vendored search-row renderer displays the asset name and market separately.
- In the current development workspace, strict Clippy reports `type_complexity` and `collapsible_if` in the Kraken catalog code. The all-features workspace test run also failed the market-settings test with the saved VibesTrader credential selected and the timeframe-menu test while looking for the 5-minute control. These checks need independent, deterministic fixtures and follow-up; the focused crypto-search and live Kraken metadata tests passed.
- TradeCraft's own source is MIT-licensed; third-party assets and dependencies retain their own terms.
- Craft's shared workflow calls for changes to reach `main` through pull requests. The initial application was pushed directly to `main` before this audit; future publication should follow a reviewable branch/PR workflow.
