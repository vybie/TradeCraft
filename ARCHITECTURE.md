# Architecture and standards audit

TradeCraft is an independent alpha application, not an official Craft app. This audit compares the project with the [shared Craft contributor rules](https://github.com/storytold/craft-contrib), including the [core house rules](https://github.com/storytold/craft-contrib/blob/main/standards/house-rules-core.md) and [Rust house rules](https://github.com/storytold/craft-contrib/blob/main/standards/house-rules-rust.md). The workspace layering pattern is informed by the public [Craft Anything architecture](https://github.com/storytold/craft-anything/blob/main/AGENTS.md); project-specific requirements in that document are not automatically universal Craft requirements.

## Workspace

Dependencies point down this list:

1. `tradecraft-core`: market bars, intervals, and timestamps. It has no UI or provider dependencies.
2. `tradecraft-providers`: Yahoo and Tradier adapters, credential storage, and settings persistence. It uses the core market types, not chart-widget types.
3. `tradecraft-engine`: candle and workspace state, a command registry, a bounded JSON command runner, provider settings, and the background market-stream lifecycle. It does not depend on egui.
4. `tradecraft-ui-egui`: egui chart rendering and the desktop interface. It translates core bars into chart-widget bars.
5. `tradecraft`: the desktop entry point.

`cargo xtask layers` checks direct workspace dependency direction and prevents core, provider, and engine crates from directly depending on UI toolkits. `cargo xtask licenses` checks the Windows normal dependency graph with all workspace features against the Craft allowlist and currently reports failures described below. A different Cargo target can be supplied, for example `cargo xtask licenses aarch64-apple-darwin`; that target's dependency metadata must be available locally. Run `cargo test --workspace` for the community configuration and `cargo test --workspace --all-features` to include the personal credential feature.

## Community release disclosure

This document is the public log of TradeCraft's Craft architecture and standards findings. Open findings do not by themselves prevent an informal community preview on the project owner's GitHub; the project does not claim full Craft compliance while they remain open. For each release, update this log with the current findings and check results, link the version of this document associated with the release in the release notes, and include it with any downloadable release package. Do not suppress or weaken checks to make the log look clean. Third-party license obligations and market-data distribution rights remain separate matters to review and disclose.

### 0.2.0 release audit (November 12, 2026)

- `cargo xtask layers`: passed for the current workspace.
- `cargo test --workspace --locked --offline` and `cargo test --workspace --all-features --locked --offline`: passed. Network-dependent and manual visual tests are ignored in the standard run. A separate controlled reconnect test used Tradier history; a real interruption during active market hours remains unverified.
- `cargo clippy -p tradecraft-providers -p tradecraft-ui-egui --all-targets --all-features --locked --offline -- -D warnings`: passed. Both personal and community release builds were rebuilt after the reconnect change.
- `cargo xtask licenses`: failed as expected under the current Craft allowlist. Findings: `adler2`, `bytemuck`, `bytemuck_derive`, `byteorder-lite`, `csv`, `csv-core`, `cursor-icon`, `egui-charts-terminal`, `foldhash`, `glow`, `memchr`, both `miniz_oxide` versions, `raw-window-handle`, `ryu`, and `self_cell`. Most declare alternative licenses, but the rule checks every identifier. The terminal manifest declares none.
- The normal Windows dependency graph was checked with all features; other targets and build/dev dependencies remain outside this check. A failed house-rule check is not itself a determination that all listed dependencies prohibit distribution. Third-party notices and applicable obligations still need their own review.
- Some Cargo packages omit license files. The community package includes an inventory and locally available notices plus additional upstream texts; see `licenses/upstream/README.md` for provenance and missing exact-revision notices. The packaged egui revision was not available from its advertised upstream repository during this audit.
- The Yahoo endpoint's distribution rights remain unresolved. The GitHub release package must include this audit and appropriate third-party notices; do not imply Craft endorsement or full compliance.

## Findings and remaining work

- TradeCraft began as a single binary crate, with market data coupled to `egui-charts` and live candle logic in the UI. The workspace now has separate crates and a UI-independent engine. Existing Git history is preserved; the initial commit was made after the initial code already existed and cannot be changed without rewriting history.
- The upstream egui-charts terminal owns the live GUI's chart, indicator and layout state. The existing engine remains UI-independent and supports the isolated `--commands` and `--script <path>` interface; those commands do not control the terminal window. The terminal feed adapter is in the UI crate and calls the provider and engine layers. A comprehensive command registry covering every UI action and an MCP server are not implemented.
- The egui-charts source is vendored at `vendor/egui-charts`. Its upstream revision is recorded in `vendor/EGUI-CHARTS-UPSTREAM`; local modifications include host integration, data services and session controls. The scheduled GitHub workflow compares that revision with upstream `main` and opens or updates an issue when they differ. It does not merge changes automatically. Review the full vendored diff when updating the dependency; retain its upstream license files, font and icon notices.
- The terminal's file storage saves named documents using encoded names and a temporary-file rename. Saved layout and drawing restoration, crash recovery, and multi-process conflicts need further verification. Alerts are in memory and operate only while the app runs. Tradier charts and watchlists share one dynamically updated market stream; initial quotes use REST snapshots. Yahoo watchlist quotes use delayed REST data. Symbol search uses the selected provider. Pine is not implemented.
- On a Tradier stream reconnect, chart recovery requests the missing historical range, restores completed bars, then reconciles the forming candle using complete one-minute bars and buffered later ticks. The chart reports recovery or errors; Tradier's intraday retention limits apply. Initial-load history overlap, provider corrections and late trade reconciliation remain open, and recovery under real market-hour interruptions needs further verification.
- Production crate roots forbid unsafe code and deny the Craft-listed panic-related Clippy lints. HTTP responses, WebSocket message/frame sizes, the market-event queue, scripts, and workspace collections are bounded. Stopping a session releases a producer waiting on a full queue. A broader input/resource audit remains incomplete.
- The existing Windows normal dependency graph contains license expressions with identifiers outside the Craft allowlist, including Zlib, 0BSD, BSL-1.0, GPL-2.0-only and Unlicense. `foldhash` (Zlib) is used through the egui/wgpu stack. The TLS adapters now use the operating system's trusted certificate store instead of the `webpki-roots` dependency, removing the latter's CDLA-Permissive-2.0 from the normal graph. `cargo xtask licenses` intentionally fails until the remaining reported entries are resolved. Other target platforms and build/dev dependencies need a separate audit. The embedded default-font notices are recorded in [ATTRIBUTION.md](ATTRIBUTION.md).
- Enabling the upstream terminal adds three further Windows license-check findings: `csv` and `csv-core` report `Unlicense/MIT`, and `egui-charts-terminal` declares no package license in its manifest. The upstream repository states MIT or Apache-2.0 licensing; package-level attribution and compliance require review. The user elected to track these issues here while continuing the integration. The checker remains unchanged and continues to report them.
- As of November 2026 the shared Rust rules say every identifier in an SPDX expression must be on the allowlist, even in an `OR` expression. That is stricter than simply choosing an offered MIT or Apache-2.0 alternative. The [VectorCraft lockfile](https://github.com/storytold/vectorcraft/blob/main/Cargo.lock) also lists `foldhash` and `memchr`, while its [desktop manifest](https://github.com/storytold/vectorcraft/blob/main/apps/vectorcraft/Cargo.toml) describes some dependencies with expressions containing Zlib. A lockfile can include inactive dependencies, so this is not evidence of an approved exception or of what VectorCraft ships. Clarification from the Craft maintainers, or tested compatible replacements that satisfy the rule as written, is needed before claiming compliance.
- The Yahoo endpoint is unofficial and Yahoo restricts automated access. Distribution rights and a suitable replacement data source remain unresolved.
- TradeCraft's own source is MIT-licensed; third-party assets and dependencies retain their own terms.
- Craft's shared workflow calls for changes to reach `main` through pull requests. The initial application was pushed directly to `main` before this audit; future publication should follow a reviewable branch/PR workflow.
