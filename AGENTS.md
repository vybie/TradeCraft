# Personal builds

All TradeCraft application changes must be included in both the personal and community executables. Keep their provider settings in separate files; retain the personal-only VibesTrader credential shortcut in the personal build. After each change, rebuild both executables and verify both updates succeeded. Never treat a pending executable as an updated taskbar pin.

Every feature and application change must also be implemented and maintained for macOS on the `codex/macos-build` branch, alongside the personal and community Windows builds. Keep feature behavior aligned across all three, adapting operating-system integrations as needed. Build and test the macOS version in an available macOS environment; if that environment is unavailable, clearly report that macOS validation remains outstanding.

Track upstream egui-charts commits and releases using the scheduled GitHub workflow and the revision in `vendor/EGUI-CHARTS-UPSTREAM`. Review new changes for useful features, fixes, compatibility and licensing; preserve TradeCraft's local modifications. Validate any adopted update for the personal Windows, community Windows and macOS builds, and record relevant changes and outstanding compatibility or compliance issues.

When building or updating the user's personal TradeCraft executable, run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-personal.ps1`. The taskbar pin targets `target/personal/tradecraft.exe`; the script updates and verifies that stable path after a successful release build with `vibestrader-credential`. Community builds must not replace the personal executable. A running window continues using the previous image until fully quit and reopened. If the pinned path cannot be updated, report the failure; do not silently leave it on an old build.
